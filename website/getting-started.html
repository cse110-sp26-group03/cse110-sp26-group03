Getting started

Install Manta, run your first commands, and learn where issue data is stored.

Prerequisites

Manta requires Bun. Install once:

curl -fsSL https://bun.sh/install | bash

Restart your shell, then verify:

bun --version

Install from npm

bun install -g manta-it

Package: npmjs.com/package/manta-it

Or run from source

git clone https://github.com/cse110-sp26-group03/cse110-sp26-group03.git
cd cse110-sp26-group03
bun install
bun link

bun link registers the mt command globally on your machine.

Try it

mt version

mt create "Issue name" --priority p1 --assignee bob

mt update manta-xxxx --status in_progress

mt view

mt sync

Replace manta-xxxx with the ID printed by your first create. Short IDs work too (e.g. mt view tzdb).

Who is recorded on each issue?

createdBy and updatedBy are filled automatically from your OS username (USER on Mac/Linux, USERNAME on Windows). You do not set them manually.

Where your data lives

Manta creates a .manta/ folder in your current working directory:

  • .manta/manta.jsonl — event log (source of truth; commit this to git)
  • .manta/manta.db — SQLite cache for fast reads (do not need to commit)

Staying in sync with teammates

After a git pull that updates .manta/manta.jsonl:

  • Any write command (create, update, close, delete) refreshes the cache automatically.
  • If mt view looks stale right after a pull, run mt sync to refresh without creating an issue.
